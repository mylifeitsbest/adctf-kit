# Подготовка за 3 часа (делать СЕЙЧАС, пока есть интернет)

Цель: завтра у вас интернета почти нет. Всё нужное надо собрать и затащить на игру сегодня.
Способ затащить: **публичный GitHub-репозиторий** → завтра `git clone` (GET разрешён). Внешние диски нельзя.

## Шаг 0. Завести «боевой» репозиторий (10 мин)
1. Создайте публичный репо на GitHub (например `adctf-kit`). Да, публичный — иначе не склонируете без логина.
   Не кладите туда токены/пароли — их впишете руками на игре.
2. Склонируйте туда: этот гайд (папка целиком), DestructiveFarm, ваши шаблоны/скрипты.
3. Проверьте, что `git clone https://github.com/<вы>/adctf-kit` работает с чистой машины.

## Шаг 1. Ферма флагов (30 мин) — КРИТИЧНО
Без фермы один человек не успеет сабмитить флаги руками — потеряете почти всю атаку.
1. `git clone https://github.com/DestructiveVoice/DestructiveFarm` (или любой форк) в репо.
2. Прочитайте [03_farm_submit.md](03_farm_submit.md). Разберитесь с конфигом ЗАРАНЕЕ: протокол `forcad`,
   поля `SYSTEM_URL`, `SYSTEM_TOKEN`/`TEAM_TOKEN`, `FLAG_FORMAT`, `SUBMIT_PERIOD`, лимит флагов за отправку.
3. Запустите локально хоть на пустом — убедитесь, что веб-морда поднимается (`docker compose up` или `python3 server/app.py`).
4. Положите рядом `scripts/submit_min.py` — запасной минимальный сабмиттер на случай, если ферма закапризничает.

## Шаг 2. Шаблоны эксплойтов (30 мин)
1. Положите `scripts/sploit_template.py` в репо. Прочитайте [04_exploit.md](04_exploit.md).
2. Потренируйтесь мысленно: эксплойт получает IP жертвы, тянет свой flag_id из attack_data, дёргает сервис, выводит флаг в stdout. Ферма сама собирает флаги из stdout.
3. Поставьте локально: `pip install requests pwntools`. Завтра поставите на боевой из PyPI (разрешён).

## Шаг 3. Скрипты защиты (20 мин)
Положите в репо и прочитайте:
- `scripts/capture.sh` — ротационный tcpdump (запустить на vulnbox в 10:00).
- `scripts/backup.sh` — бэкап сервиса (tar + дамп docker volume).
- `scripts/portaudit.sh` — что торчит наружу.
- [01_hardening.md](01_hardening.md), [02_firewall.md](02_firewall.md) — чеклисты, выполнять по бумажке.

## Шаг 4. Скачать то, чего может не быть в репах (20 мин)
Пакеты из реп завтра поставятся (`apt`), PyPI/npm доступны. Но на всякий случай соберите в репо:
- `tshark`, `ngrep`, `tcpdump` — обычно есть, но проверьте названия пакетов.
- `tulip` (анализатор A/D трафика) — опционально, если успеете разобраться; иначе хватит tshark+grep.
- Любимые ваши ваппы: nmap, netcat, socat, jq.

## Шаг 5. Распечатать/записать шпаргалку команд (10 мин)
Короткий текстовый файл с командами, который не надо гуглить:
- сброс root-пароля через GRUB (`init=/bin/bash`);
- `ss -tulpn`, рестарт sshd, `sshd -T | grep -i password`;
- запуск tcpdump, grep флага в pcap;
- запуск фермы.
Всё это уже есть в этих файлах — просто держите их открытыми.

## Шаг 6. Договориться о ролях (10 мин)
Прочитайте всей командой [06_roles.md](06_roles.md) и распределитесь. Решите, кто в 10:00 бежит на защиту, а кто сразу на tcpdump+разведку.

## Чего НЕ делать в подготовке
- Не тратьте время на изучение незнакомых тяжёлых тулов (Tulip, свои фреймворки), если нет уверенности. Базовый tcpdump+grep+ручной реплей надёжнее.
- Не пишите эксплойты заранее «вслепую» — сервисов вы ещё не видели. Готовьте **шаблон и инфраструктуру**, а не конкретные сплойты.
